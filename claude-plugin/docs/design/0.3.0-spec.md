# RePoG Claude Code Plugin 0.3.0 — Design Spec

Status: approved scope (2026-10-19). Baseline: plugin 0.2.0 (typed owner ops,
`commit-distill`, curation warnings, `session_report`).

## 1. Why

A 779-turn live session (Turkish, low-fantasy) showed failure classes that are
not specific to that language, world, or tone:

1. Facts lost after context compaction; the GM rarely re-reads character notes
   (dead relative treated as alive, kinship and gender flips, people placed in
   scenes they left).
2. Records only grow (stacked "Current State (day N)" sections, 980 KB log).
3. Knowledge leaks (an NPC uses a secret name; a mother "knows" a baby's sex).
4. Hollow mechanics: a dice scale exhausted by progression, rolls with Python
   `random`, difficulty never declared before the roll, a complication added on
   a success, no social or investigation rolls.
5. Threats closed off-screen in time skips; NPCs hand over solutions.
6. Time skips done by hand; relationships under-weighted; wages double-charged.
7. The GM restates the Player's input (28-58% of replies) and writes the PC.
8. Presentation: translationese tics, English status lines, tracker numbers in
   prose, wrong address forms, name collisions with common words.
9. OOC corrections pile up as unenforced prose rules.
10. Latency: a durable turn waits ~62 s, half of it bookkeeping.

Every mechanism below must work for any play language, setting, and tone.
Language- or setting-specific knowledge lives in data packs and campaign
files, never in code.

## 2. Product decisions (from the maintainer)

- Same plugin name `repog`, version `0.3.0`, replaces the installed copy.
- Four behaviors that amend the shared contract are profile switches, all
  **default on** when the switch is absent:

```yaml
# play_profile.yaml
runtime:
  persistence_order: narrate_then_commit   # | commit_then_narrate
  presentation_lint: on                    # | off
  scene_capsule: on                        # | off
  boundary_curator: background             # | inline | off
narration:
  language: auto                           # BCP-47 primary subtag (tr, en, de...) or auto
```

`tools/repog_runtime.py` (already written) reads these with defaults:
`runtime_settings(campaign)`.

## 3. Runtime area

`campaign/.repog-runtime/` holds working files that are never fictional
authority. Deleting it loses no truth. Files:

| File | Owner | Content |
| --- | --- | --- |
| `capsule_state.json` | scene_capsule | per session id: section hashes last injected, turn counter |
| `lint_last.json` | presentation_lint | findings for the latest reply |
| `lint_history.jsonl` | presentation_lint | per-reply rule counts and n-gram fingerprints, newest 400 |
| `rolls.jsonl` | roll_dice | roll receipts (append-only, newest 2000) |
| `curation/<id>.json` | curator agent | staged `commit-curation` payloads |
| `curation/applied/`, `curation/rejected/` | rpg_state | processed staging files |

Helpers in `repog_runtime.py`: `find_campaign`, `runtime_dir`,
`runtime_settings`, `is_ready_rpg`, `state_summary`, `last_turn(transcript)`,
`read_json`, `write_json_atomic`, `append_jsonl`, `read_jsonl`.

## 4. Components

Each component lists its files. **Stage 1 agents create or modify only their
own files plus their own tests.** Shared files (`rpg_state.py`,
`check_state.py`, `narrative_memory.py`, `hooks/hooks.json`, `scripts/*`,
`skills/play/SKILL.md`, `AGENTS.md`, `workflows/**`) are integrated in Stage 2.

All Python: 3.10+, standard library only, type hints, small functions,
deterministic, no network, no model calls, UTF-8 everywhere (Windows!). Tests:
pytest under `tests/`, synthetic content only (never the real campaign), import
tools via `tests/conftest.py` (adds `plugin/tools` to `sys.path`).

### A. Language packs and name check

Files: `plugin/packs/languages/{tr,en,de,es,fr}.json`,
`plugin/packs/languages/{tr,en}.md`, `plugin/tools/lang_pack.py`,
`plugin/tools/name_check.py`, `tests/test_lang_pack.py`,
`tests/test_name_check.py`.

Pack JSON schema (all keys optional except `code`, `name`, `stopwords`):

```json
{
  "code": "tr",
  "name": "Türkçe",
  "casefold": "turkish",            // "turkish" maps I->ı, İ->i before casefold; else "default"
  "stopwords": ["ve", "bir", "bu", ...],      // 80-200 very common function words
  "avoid_phrases": [{"phrase": "bir an", "max_per_reply": 1, "note": "overused beat"}],
  "negated_description": ["regex ..."],       // e.g. "\\b\\w+m[ıiuü]yor(du)?,?\\s+ama\\b"
  "day_patterns": ["regex ..."],              // tracker day numbers in prose: "\\b\\d+\\.\\s*gün\\b", spelled ordinals + "gün"
  "pc_speech_patterns": ["regex ..."],        // narration attributing speech/acts to the second-person PC: "\\bdedin\\b"
  "meta_words": ["revizyon", "kayıt dosyası", ...],  // backend vocabulary in this language
  "calques": [{"bad": "yüzünde hiçbir şey yoktu", "better": "yüzünden hiçbir şey okunmuyordu"}],
  "common_words": ["tam", "kara", ...],       // short frequent words a character name must not equal
  "card": "One paragraph, <=600 chars, English, telling the model how to write natural prose in this language (address forms, register, typical calques to avoid)."
}
```

Seed `tr` from the live-session evidence: avoid phrases `bir an`,
`başka bir şey demedi/söylemedi/eklemedi`, `cevabını bekliyor`, `sesi
titremiyordu`; calques from the campaign's `turn_reminder.md` list (yüzünde
hiçbir şey yoktu, sesi düzdü, gözleri ... üstünde kaldı, bir şeyi tartıyordu,
ne eksik ne fazla, surlarda çok yakışıyorsun); day patterns for digits and
spelled ordinals ("doksan ikinci gün"); `çeyrek saat` as an anachronism
example belongs to setting glossaries, not the pack; sen/siz guidance in the
card; common words including `tam`, `kara`, `ak`, `er`, `bay`, `han`, `bey`,
`ay`, `can`, `nur`. `en`: stopwords, "a moment", "said nothing else", "did not
waver" negation, "day \\d+" patterns, "you said/asked/replied" PC patterns,
meta words (revision, commit, payload, schema, helper, campaign file). `de`,
`es`, `fr`: stopwords (≥80) plus PC speech patterns and day patterns; the rest
optional. `.md` packs (tr, en): 1–2 KB of model guidance with 6–10 short
natural exemplar lines and register notes.

`lang_pack.py` API:

- `load_pack(code: str) -> dict` (cached; unknown code → `{"code": code, "stopwords": []}`)
- `available_codes() -> list[str]`
- `fold(text: str, pack: dict) -> str` locale-aware casefold
- `detect_language(text: str, candidates: list[str] | None = None) -> tuple[str | None, float]`
  by stopword hit ratio over words (≥ 8 words, else `(None, 0)`); confidence =
  best ratio minus second best.
- `sentence_split(text: str) -> list[str]` handling `.!?…` and quotes, any
  script.
- `count_phrase(text, phrase, pack) -> int` word-bounded, folded (so "bir an"
  does not match "bir anahtar", "İçini" matches "içini").

`name_check.py` API:

- `check_name(name: str, existing: list[str], pack: dict) -> list[dict]`
  returning warnings `{rule, message}` for: `name_common_word` (any token of
  the name, folded, equals a pack common word); `name_near_duplicate`
  (Levenshtein ≤ 1 for names ≥ 4 chars, ≤ 2 for ≥ 7, ignoring case; e.g.
  Corran/Corlan, Halvar/Harlan, Hilda/Hilde); `name_same_initial_sound` only
  as info when the first 3 letters match and lengths are within 1.
- `levenshtein(a, b) -> int`.

### B. Presentation lint

Files: `plugin/tools/presentation_lint.py`, `tests/test_presentation_lint.py`.

`lint_reply(prompt: str, texts: list[str], descriptions: list[str], *,
pack: dict, context: dict, history: list[dict]) -> dict` — pure function.
`context` carries `day`, `revision`, `player_name`, `protected_names`
(list of `{name, holders, status}`), `avoid_phrases` (campaign list),
`glossary_variants` (list of `{variant, preferred}`), `play_language`.

Rules (each finding: `{rule, count, evidence: [<=3 snippets of <=80 chars]}`):

1. `out_of_language` — sentences (≥ 6 words) whose detected language is not
   the play language with confidence ≥ 0.15; also tool descriptions (visible
   to the Player) in another language.
2. `meta_leak` — file paths (`\w+/\w+\.(md|yaml|json|py)`, `campaign/`,
   `tools/`), backticks, snake_case identifiers with ≥ 2 underscores, pack
   `meta_words` and English backend words (revision, commit, payload, schema,
   helper, operation id) when they appear outside quotes.
3. `tracker_leak` — the current day number or continuity revision as digits
   in narration, and pack `day_patterns`.
4. `avoid_phrase` — pack and campaign avoid phrases above their per-reply cap.
5. `repetition` — word 3- to 5-grams (folded) that appear in ≥ 3 of the last 8
   replies including this one (history supplies earlier fingerprints); report
   the top 3.
6. `restatement` — the reply's first 60 words reuse ≥ 50% of the prompt's
   content words (folded, length ≥ 4, at least 5 such words in the prompt).
7. `pc_authoring` — pack `pc_speech_patterns` matches; evidence only, the GM
   judges.
8. `secret_leak` — a protected name whose status is not revealed/PC-known
   appears in the reply.
9. `negated_description` — pack patterns, reported when ≥ 2 in one reply.
10. `glossary_variant` — a known variant appears instead of the preferred form.
11. `calque` — a pack `calques[].bad` phrase appears.

Also returns `fingerprint` (list of folded 4-gram hashes, ≤ 300) and
`summary` (≤ 400 chars, English, e.g. `Last reply: 3x "bir an" (cap 1); 1
English line: "Saving the scene"; opening restates the Player's words.`), or
an empty summary when clean.

`run_hook(stdin_json: dict) -> None`: locate the campaign from `cwd`, skip
unless ready RPG and `presentation_lint` on, read `last_turn(transcript_path)`,
load pack (`language` setting; `auto` → detect from the last 5 prompts in
history plus this prompt, store the detection in `lint_last.json`), build
context from campaign files (`knowledge_boundaries.md` "Protected Proper
Nouns": `### Name` entries with `- Status:` and `- NPCs or factions who
know:`; `style_state.json` `avoid_phrases`; `play_profile.yaml`
`narrative_signature.avoid_habits`; optional `glossary.md` table with columns
`Term | Preferred | Variants`), write `lint_last.json`, append history. Must
finish in < 1 s on a 125 MB transcript (tail read) and never raise.

CLI: `python tools/presentation_lint.py hook` (reads hook JSON on stdin);
`python tools/presentation_lint.py report <campaign> [--last N]` prints
aggregate counts per rule over history (for distill review).

### C. Scene capsule

Files: `plugin/tools/scene_capsule.py`, `tests/test_scene_capsule.py`.

`build_capsule(campaign: Path, prompt: str, *, session_id: str, settings:
dict, full: bool | None = None) -> str` and `run_hook(stdin_json) -> str`.

Sections (each with a stable key; delta mode emits only changed sections):

1. `header` (always): `RePoG capsule — rev N · day D phase P · <location> ·
   scene <scene_id> · persistence: <order>`; plus `Full distill is due after
   this turn's commit.` when `durable_turns_since_distill` ≥ the policy
   threshold − 1.
2. `cast`: for each entity in scope (present NPCs, then names found in the
   prompt, then names recorded from the previous reply in
   `capsule_state.json`, max 8): name, note path, `## Core` fields if present
   (Status, Pronouns and address, Kin, Role, Home, Speaks); else Tier + Agency
   Card lines `Voice rhythm`, `Social tactic`, `Hard boundary`, `Routine and
   availability`; then the first 300 chars of `## Now` / `## Current State`
   (the last such section if several); relationship rows with the PC from
   `relationship_map.md` (Relation, Status, first 160 chars of the next
   column); the NPC's knowledge block from `knowledge_boundaries.md` (`### Name`
   under the NPC knowledge heading, first 400 chars). Kin lines naming a dead
   relative are kept verbatim.
3. `secrets`: for entities in scope, protected names they do NOT hold:
   `Edric: not a holder of F-007` (ids only, never the secret text).
4. `directives`: active rows from `directives.md` (`| Id | Scope | Directive |
   Source | Status |`) whose scope is `global`, the current scene id, or an
   entity in scope; max 12, newest first.
5. `language` (full capsule only): the pack `card`, the configured or detected
   language, and the campaign's address/title notes if `glossary.md` has them.
6. `lint`: `lint_last.json` summary when non-empty.
7. `rolls`: unconsumed roll receipts at the current revision (from
   `rolls.jsonl`) — `roll <id> (<actor> <axis> vs <difficulty>): <band>,
   not yet committed`.
8. `curation`: staged curation files waiting to be applied, by id.

Entity matching: character note titles (first `# ` heading) and file stems,
plus aliases from a `- Aliases:` Core line; match whole words, folded with the
language pack; ignore names shorter than 3 letters.

Full vs delta: full on the first prompt of a session id, after
`capsule_state.json` marks the session reset (SessionStart compact/clear
writes the reset flag via `scene_capsule.py reset --session <id>`), when the
scene id changes, or every 12th prompt; otherwise only sections whose hash
changed, plus the header. Size: full ≤ 6,000 chars, delta ≤ 2,000; truncate
per section with `…`.

Output for the hook: return the capsule text; the hook wrapper decides the
JSON envelope (Stage 2). Must finish in < 1 s and never raise.

### D. Mechanics integrity

Files: `plugin/tools/roll_dice.py` (extend, keep the old CLI working),
`plugin/tools/odds.py`, `tests/test_roll_call.py`, `tests/test_odds.py`.

Resolution config (optional, in `play_profile.yaml`):

```yaml
mechanics:
  resolution:
    die: 1d2              # any NdM
    stat_min: 1
    stat_max: 5
    difficulty_min: 1
    difficulty_max: 5
    auto_success_margin: 2     # stat - difficulty >= this succeeds without a roll; omit for none
    bands:                     # margin = total - difficulty; first match wins
      - {at_least: 0, band: success}
      - {at_least: -1, band: partial_small_cost}
      - {at_least: -2, band: partial_medium_cost}
      - {at_least: -99, band: partial_heavy_cost}
```

Read it with a small parser in `odds.py`: `load_resolution(play_profile_text)
-> dict | None` (inline-mapping list items as above).

Roll call (`roll_dice.py --campaign <path> --input-json {...}`):

```json
{"call": {"actor": "Marcus", "axis": "street_sense", "value": 5,
          "difficulty": 6, "factors": [{"label": "prepared ambush", "modifier": 1}],
          "stakes": "the bait is seen through and the men scatter"},
 "roll_id": "bait-feint"}
```

- Requires `call.actor`, `call.axis`, integer `value`, integer `difficulty`,
  non-empty `stakes`; `factors` optional (integer modifiers, labels ≤ 80).
- Seed = sha256(campaign_id, continuity_revision, roll_id, canonical call) —
  never caller-supplied in call mode, so a re-roll of the same call returns the
  same receipt (idempotent) and shopping needs a new roll id, which stays on
  record.
- total = value + sum(modifiers) + die; margin = total − difficulty; band from
  `resolution.bands` (or `success`/`failure` at margin ≥ 0 when no config);
  `auto: true` when `value + modifiers − difficulty ≥ auto_success_margin`
  (no die rolled, band = first band).
- Validates `value` within stat range and `difficulty` within difficulty
  range when a resolution config exists; out of range → error naming the
  range ("raise the scale through an OOC rules change first").
- Appends a receipt to `campaign/.repog-runtime/rolls.jsonl`:
  `{roll_id, revision, call, dice, total, margin, band, auto, at}` and prints
  it. Same roll_id + same call at the same revision → returns the stored
  receipt (`"repeat": true`). Same roll_id with a different call → error.
- Library functions for Stage 2: `find_receipt(campaign, roll_id) -> dict |
  None`, `open_receipts(campaign, revision) -> list[dict]` (receipts at that
  revision not yet marked consumed), `mark_consumed(campaign, roll_ids,
  revision)` (rewrites the jsonl atomically, adds `consumed_revision`).

`odds.py`:

- `success_table(resolution) -> dict[(stat, difficulty)] -> {band: probability}`
  exact, by enumerating the die.
- `exhaustion(resolution) -> list[str]` warnings: for `stat_max`, every
  difficulty ≤ difficulty_max gives P(first band) = 1 → `scale_exhausted`;
  any (stat, difficulty) pair where the first band is unreachable → info.
- CLI `python tools/odds.py <campaign>` prints the table as Markdown.

### E. Downtime, clocks, ledger

Files: `plugin/tools/resolve_mechanic.py` (extend), `plugin/tools/world_pulse.py`
(extend), `tests/test_downtime_mechanics.py`.

- Clocks gain optional fields `owner` (text), `tick: {unit, amount}`,
  `on_fill` (one line). `advance_time` ticks every clock whose `tick.unit`
  equals the unit (`amount * steps`, capped at maximum) and reports
  `{"kind": "clock", ..., "filled": true}` when it reaches maximum. Validation
  accepts the new fields; old clocks unchanged.
- Obligations: `state["obligations"][id] = {actor_id, resource_id, amount,
  period_label, settled: [period keys]}`. New operations `add_obligation`
  (`obligation_id`, `actor_id`, `resource_id`, `amount` ≥ 0, `period_label`)
  and `settle_obligation` (`obligation_id`, `period` string, optional
  `amount` override): spends from the actor's resource once per period key;
  settling the same period again is an error naming the period (prevents
  double-charged wages).
- `world_pulse.py`: accept `{"domains": [ {...one domain request...}, ...]}`
  and return `{"ok": true, "results": [...]}` in the same order, each
  identical to a single-domain call; keep the single form working. Cap 12
  domains.

### F. Boundary curator

Files: `plugin/agents/repog-curator.md`, `plugin/tools/curation.py`,
`tests/test_curation.py`.

- Agent frontmatter: `name: repog-curator`, description (when to use: after a
  full distill or at an act/skip boundary when the writer or full check
  reported `stacked_sections`, `owner_size_budget`, stale projections, or
  notes missing a `## Core` block), `tools: Read, Grep, Glob, Write`,
  `model: inherit`. Body: it receives a frozen packet (campaign path, base
  revision, target files with reasons, the play language, directives that
  constrain notes); it reads the targets and writes exactly one file,
  `campaign/.repog-runtime/curation/<curation_id>.json`, never anything else;
  it never invents facts, keeps every qualifier and holder limit, folds
  stacked dated sections into one `## Now` section plus a short `## History`
  line list, adds a `## Core` block from facts already in the note or owners,
  keeps Player/OOC directives verbatim, writes speech samples in the play
  language. Its final message is one line: the staged path.
- Staged payload = `{curation_id, base_revision, reason, base_hashes:
  {path: sha256}, mutations: [typed ops as in persistence playbook 3D]}`.
- `curation.py` API (Stage 2 wires it into `rpg_state commit-curation`):
  `file_hash(path) -> str`; `validate_staged(campaign, payload) -> list[str]`
  (errors: unknown keys, missing hash for a mutated path, paths outside the
  allowed set = Markdown files except `session_log.md`, archive, runtime);
  `split_by_freshness(campaign, payload) -> (fresh_mutations, stale_paths)`
  comparing current hashes; `list_staged(campaign) -> list[Path]`;
  `move_processed(path, outcome)`.

## 5. Stage 2 integration (serial)

1. `rpg_state.py`:
   - `SCENE_MODES` += `downtime`.
   - Roll verification when dice mode is active: a change may carry
     `roll_reference` and `outcome`; the reference must match a receipt
     (`roll_dice.find_receipt`), `outcome` must equal the receipt band; on
     commit mark receipts consumed. Receipts made at the base revision and not
     referenced must be listed in a new optional payload field `void_rolls:
     [{roll_id, reason}]`, else `rolls_unaccounted` error. Legacy free-text
     references stay accepted when no receipt store exists (warning).
   - `commit-curation` subcommand: applies fresh staged mutations (curation
     path rules = distill rules), stamps, appends `### Curation Applied At
     Revision N` with id and reason, moves the staged file; stale files are
     reported and moved to `rejected/`. No revision, no counters. Also
     `--apply-staged` to process every staged file.
   - `create_text` of a new entity note runs `name_check` against existing
     note titles and the language pack → `warnings`.
2. `check_state.py`: configurable stat scale from `mechanics.resolution`
   (fall back to 1–5); `scale_exhausted` warning from `odds.exhaustion`;
   validate `runtime:` and `narration.language`; warn T2/T3 notes without
   `## Core` (`note_core_missing`, warning) and notes whose Core Status is
   `dead` while listed in `present_npcs` (`dead_present`, error).
3. `narrative_memory.py`: closing a thread (status to resolved/closed) without
   a `Resolution:` line → warning `thread_closed_without_resolution`.
4. Hooks (`hooks/hooks.json` + `scripts/`): `UserPromptSubmit` →
   `scripts/prompt-hook.sh` (applies ready staged curation when the curator is
   `background`, then prints the capsule in the documented envelope);
   `Stop` → `scripts/stop-hook.sh` (presentation lint, silent);
   `SessionStart` → existing reminder plus capsule reset; optional
   `PreToolUse` guard for the curator if subagent identity is available.
   All wrappers: POSIX sh, LF, never fail the turn (always exit 0 unless
   documented otherwise), silent outside a ready RPG campaign, Python via the
   same probe as `repog.sh`.
5. Text: `AGENTS.md` amendments (plugin copy and the copy inlined in
   `skills/play/SKILL.md`, which must stay ≤ 19,000 bytes), GM workflow,
   persistence playbook (narrate-then-commit procedure and failure rule),
   distill workflow (curator), ooc_adjustment (directives), action_conflict /
   dialogue_social / exploration_investigation (declare-before-roll, social
   and investigative rolls, no handed solutions), travel_downtime (skip
   procedure with required sections from the Player's priorities, approval,
   one commit, clocks, obligations), scene_arc_transition (thread closure
   evidence), README.

## 6. Contract amendments (exact intent)

- Persistence order: with `narrate_then_commit` the GM resolves the turn,
  decides the semantic capture, writes the reply, then makes one commit call
  and writes nothing after it. A failed commit is fixed and retried in the
  same turn; if the fact cannot be persisted as narrated, a one-line OOC
  correction follows. With `commit_then_narrate` the old order holds.
  A due full distill runs after the reply in the same turn.
- Presentation lint is deterministic, model-free, warning-only, runs after
  the reply, and its summary reaches the GM in the next capsule. It is not
  the forbidden semantic checker.
- The scene capsule is a deterministic read of owners; owners stay
  authoritative.
- The boundary curator proposes typed edits to secondary and note content
  through a staging file; the deterministic writer applies them only when the
  base hashes still match. It never creates new truth, revisions, or markers.

## 7. Acceptance

- `python -m pytest tests` green; new tests per component.
- Universality: lint and capsule tests cover tr, en, and de fixtures.
- A smoke run on a copy of the live campaign: capsule full + delta, lint on
  the real last turn, roll call + commit verification, commit-curation with a
  stale and a fresh file, full check 0 errors.
- Skill ≤ 19,000 bytes; hooks silent outside RPG campaigns.

## 8. Implementation notes (where the build departs from this spec)

- Runtime files: `capsule_names.json` (written only by the Stop hook: names in
  the last reply) joins the table in section 3; the prompt hook only reads it,
  so an async Stop hook can never erase a compaction reset.
- Presentation lint, `restatement`: flags only an echo in the reply's opening
  (a run of >= 4 consecutive prompt words, endings allowed to differ by a
  shared 4-letter prefix, with >= 2 content words; or a quoted span of >= 3
  words matching the Player's quoted words), never topical overlap.
- Presentation lint, backend vocabulary: English play counts only the en
  pack's unambiguous collocations ("durable commit", "session log", ...);
  other languages also count the English backend words unless the word is
  native vocabulary there (German "Revision", "Schema") or a stopword.
- Presentation lint: narration rules skip OOC blocks and Markdown structure;
  visibility rules (out_of_language, meta_leak, secret_leak) read everything;
  tool descriptions need one foreign function word; single-token campaign
  avoid entries of >= 4 letters match as stems.
- Scene capsule: deltas are line-level, and a person whose note switches
  between the legacy Agency Card lines and the `## Core` layout is re-sent
  whole once; roster tags are `present` and `mentioned`; a word of a
  multi-word note title counts as a given name when no other note uses it;
  holders include given names and the member's own confirmed fact ids; cuts
  happen only at clause or list boundaries.
- Dice: under `player_rolls` / `hybrid` a Player's physical roll is cited as
  `player: <what was rolled>` with its band as `outcome` (unverified). A call
  may carry an optional one-line `reason` (at most 200 characters) for its
  difficulty; it joins the canonical call, and so the seed, only when present.
  `roll_dice.py` and `world_pulse.py` also read `--input-file PATH`, or
  standard input with `--input-file -`; `resolve_mechanic.py` stays
  `--input-json` only.
- Mechanics: an obligation spends from exactly one holding, `resource_id` or
  `item_id` (money kept as an inventory item counted by quantity), under the
  same once-per-period guard; period keys compare caselessly. `add_clock` and
  `remove_clock` start and retire clocks during play. The travel playbook sets
  two conventions: `world_pulse` `elapsed_steps` counts the domain's own step
  (one week unless its `world_dynamics.md` entry names another unit), and
  period keys derive from `fictional_time.day` (`week:<day // 7>`,
  `month:<day // 30>`) so a skip cannot invent a fresh key.
- Writer: `directives.md` and `glossary.md` are owners; a typed edit to a
  missing one starts from the shipped template, and `commit-checkpoint` may
  edit both, so an OOC-only rule needs no fictional revision. A new note's
  name check also compares `creation_ledger.md` entries and the
  `active_cast.md` and `relationship_map.md` names, in the play language, and
  a new character note gets advisory `note_incomplete` warnings from the full
  check's character-note rules. `commit-curation` applies a staged file all or
  nothing and waits 3 s after the file was written.
- Curation: the prompt hook records each run that applied, rejected, or
  deferred a file in `curation/last_result.json` (a runtime file beside the
  staged ones; the id `last_result` is reserved and the curator's write guard
  refuses that file), and the next capsule shows a
  rejected or deferred proposal once. The curator may add a short
  `## Details` list after `## Now` for still-true facts that do not fit, opens
  `## Now` with a line naming the folded heading, and leaves a target its
  reason asks nothing of untouched.
- Distill: habits the lint report keeps finding are raised with the Player at
  a session pause, and a directive is recorded only if the Player wants one;
  the GM never edits `style_state.json` by hand.
- Hooks: the PreToolUse guard matches `Write` only (the curator's one writing
  tool); the interpreter probe is cached in `CLAUDE_PLUGIN_DATA`.
- Not built: the `thread_closed_without_resolution` check; the playbooks ask
  for a `Resolution:` line instead. Places are not part of the capsule cast.
